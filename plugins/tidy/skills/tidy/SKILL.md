# Tidy — 로컬 정리 (브랜치·stash / 다운로드·데스크톱)

역할이 끝난 것을 골라내 정리한다. 두 모드 모두 **스캔(읽기 전용) → 분류 → 제안 → 승인 → 실행 → 보고** 순서를 따른다.

## 모드 고르기

| 모드 | 요청 예 | 절차 문서 |
|---|---|---|
| repo | 브랜치·stash·저장소 정리, `/tidy repo` | `references/repo.md` |
| files | 다운로드·데스크톱·파일 정리, `/tidy files` | `references/files.md` (macOS 전용) |

- 요청에서 모드가 드러나면 그 문서 하나만 읽고 그대로 따른다.
- `/tidy`처럼 모드가 없으면 어느 쪽인지 한 번 묻는다. "둘 다"면 repo → files 순으로 따로 진행하고 승인도 따로 받는다.

## 공통 가드레일

- **삭제는 절대 자동으로 하지 않는다.** 항목 단위로 근거를 붙여 제안하고 승인받은 것만 실행한다.
- 되돌릴 길을 먼저 만든다: repo는 백업 태그, files는 `_trash/`·`_archive/` 이동.
- 판별이 애매하면 "확인 필요"로 내리고 건드리지 않는다.
- 조회에 실패한 소스는 실패했다고 적는다. 추정으로 채우지 않는다.
- 보고에는 정리 전후 개수·용량과 복구 방법을 함께 적는다.
